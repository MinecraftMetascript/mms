# Decision log

Judgement calls made while building the rewrite without stopping for input. Each entry says what was chosen and why, so any of them can be revisited. Newest last.

Decisions Brian made directly are recorded in the plan ([docs/plan.md](plan.md)) and are not repeated here.

| # | Date | Area | Decision | Why |
| --- | --- | --- | --- | --- |
| D1 | 2026-10-31 | Repo | The old implementation was deleted from the tree in one commit, not moved to a folder. | The old code is reference only and stays in git history (`git show 9748807:<path>`). Keeping it in the tree would confuse tooling and search. |
| D2 | 2026-10-31 | Tracking | Milestones are sub-issues of a tracking issue (#22) and carry a checklist; task sub-issues are filed per milestone when that milestone starts, not all up front. | Filing every task early would freeze a breakdown that will change as the earlier milestones teach us things. |
| D3 | 2026-10-31 | Spec pack | The spec pack is the vanilla-mcdoc symbol table filtered to 26.3, in the same node shape, plus registries, block states and the command tree, stored as gzipped JSON. It is not converted to a new normalised schema model. | Keeping mcdoc's own shape is lossless (templates, dispatchers, spreads, attributes survive), so no information is thrown away before the checker needs it. One loader in `spec` interprets it. A custom binary format can come later if size or load time need it; the generator reports both. |
| D4 | 2026-10-31 | Spec pack | Version gates: `#[since=v]` keeps a node when 26.3 >= v; `#[until=v]` keeps it when 26.3 < v. Versions compare as dotted integers. | This is how Spyglass reads the attributes. Checked against `density_function::Clamp.input`, which switches from inline-only to reference-or-inline at 26.2. |
| D5 | 2026-10-31 | Spec pack | Only resource kinds whose type lives under `::java::data::` are data-pack kinds. Asset kinds (models, atlases, fonts, lang) are dropped from the pack. | MMS targets data packs. The `minecraft:resource` dispatcher mixes both. |
| D6 | 2026-10-31 | Spec pack | Generator inputs are fetched over HTTPS from pinned commits and the generated pack is committed to the repo. | Builds, tests and the WASM bundle then need no network, and every spec change shows up as a reviewable diff. |
| D7 | 2026-10-31 | Toolchain | Go 1.24, the version installed in the dev environment and current stable. | No feature in the plan needs a newer release. |
| D8 | 2026-10-31 | Spec pack | 26.3 density function names are used as they are: `cache` (replacing `cache_2d`, `flat_cache`, `cache_once`, `cache_all_in_cell`), `gradient` (replacing `y_clamped_gradient`), `noise` with shifts (replacing `shifted_noise`), plus new math types (`sub`, `div`, `pow`, `lerp` and more). | The pinned mcdoc data and the vanilla 26.3 worldgen files both use these names, so the old MMS helpers map onto the new types. This also means Deepslate's density function support must be checked against 26.3 before the preview milestone. |
| D9 | 2026-10-31 | WASM | The spec pack is embedded in the WASM binary for now, rather than fetched as a separate static file. | The gzipped pack is 265 KB; the WASM binary with it is 3.8 MB (1.25 MB gzipped). One file is simpler to load and cache. If version selection lands, packs for other versions can be fetched on demand. |
| D10 | 2026-10-31 | WASM | Decoding the pack takes about 0.7 s in WASM (0.17 s native). Accepted for M0; revisit in M3 if the editor's time to first completion suffers. | Decoding JSON is the cost. A lazily decoded or binary pack is the known fix and can be done behind the same `spec` API. |
| D11 | 2026-10-31 | Process | All work goes to the single development branch `claude/project-thread-6fciq4`, with one pull request into `main` that grows milestone by milestone. Task issues are closed when their commits are pushed, with the commit referenced. | Only that branch is available to this session. Milestone checklists in the issues show the review boundaries. |
| D12 | 2026-10-31 | Syntax | Fields and named arguments use `=` (`rolls = 1`, `Foo(a = 1)`). `:` is reserved for resource locations and, followed by a space, type annotations (`x: int`). | One assignment token everywhere reads consistently in resources and functions, and it frees `:` so `minecraft:stone` never needs quoting. |
| D13 | 2026-10-31 | Syntax | A resource location token never contains spaces, so `a/b` is the path `a/b` and `a / b` is division. | Paths are everywhere in data packs (`blocks/ruby_ore`); division is rare and spacing it out is the house style anyway. |
| D14 | 2026-10-31 | Syntax | A raw command is a line whose first non-blank character is `/` followed by a lowercase letter, and runs to the end of the line. `{ /say hi }` on one line is an error with a dedicated message. | Commands contain arbitrary text (JSON, NBT, braces), so only a line boundary can end one safely. |
| D15 | 2026-10-31 | Syntax | Newlines are not significant; items in a block are separated by newlines or optional commas. A declaration without a name must have a block (`OnLoad { }`). | Keeps the grammar context-free and lets recovery restart at any column-0 `Kind name` line. |
| D16 | 2026-10-31 | Syntax | Assignment to a dotted path (`a.b.c = 1`) is its own statement form, `IDENT (. IDENT)+ = expr`, rather than allowing any expression on the left of `=`. | A general `expr = expr` made ANTLR mispredict half-typed fields (`rolls =`), which completion depends on. Index targets can be added later the same way. |
| D17 | 2026-10-31 | Formatter | Files with syntax errors are not formatted (the editor shows the errors instead). After formatting, the output is re-parsed and must have the same AST outline and the same comment words, or nothing is written. | Formatting a broken tree risks moving code into the wrong place; the safety check turns any printer bug into a no-op plus an error, never data loss. |
| D18 | 2026-10-31 | Formatter | Width 100, two-space indent, trailing commas in broken lists and calls, `&&`/`||` chains break before the operator, method chains of two or more calls break before each dot, lists of two or more objects always break. Authors' parentheses are kept; single blank lines between items are preserved and runs collapse to one. | Matches the house style in the plan; preserving parentheses keeps the formatter from fighting deliberate grouping. |
| D19 | 2026-10-31 | Formatter | Command text is printed verbatim apart from trailing whitespace. | Brigadier treats extra spaces as part of an argument (`say`) or as an error, so collapsing them would change behaviour. |
| D20 | 2026-10-31 | Formatter | Block state and selector arguments print without spaces around `=` (`@e[type=zombie, limit=1]`); call arguments keep them (`Foo(a = 1)`). | Index arguments read like the command syntax they lower to. |
| D21 | 2026-10-31 | Parser | The `COMMAND` lexer predicate sits after the `/` rather than at the start of the rule. | A predicate at the start stops ANTLR from caching the lexer's start state; moving it made parsing 21 times faster (1,000 lines in about 30 ms). |
